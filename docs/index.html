The core idea, running

Wall-clock = the slowest agent, not the sum.

A Baton handoff can tell the next session to fan out. Flip the switch and dispatch five subagents. In SOLO they run one after another. In SWARM they launch together — and finish in the time of the single slowest one.

Wall-clock elapsed
0.0s
If run serially
9.1s
SOLO: total time is the sum of every agent — 9.1s. Now switch to SWARM and dispatch again.
What makes Baton different

Section 0: the next session's shape.

Most handoffs say what to do next. Baton opens by declaring who does it — model tier, mode, review depth — before a single line of work begins.

The rules it encodes

Model tier — latest Sonnet for a bounded task, latest Opus to orchestrate. Written as "latest", never pinned, so handoffs never age out.

Mode — SOLO (one agent) vs SWARM (orchestrator + subagents).

Parallelism — front-load planning, then dispatch the maximum safe number of subagents at once. Guardrails hold: scoped file lists, safety-critical logic to a guardian, no self-certifying.

## 0. Receiving Session Config - Model / tier: Opus (latest) orchestrator - Mode: SWARM — orchestrator + subagents - Subagents: 5× Sonnet (latest) - Review depth: full adversarial flow - Boot: read this doc, then decompose - Directive: front-load, then fan out the max safe subagents in one batch — comprehensive and fast.

Get going

Drop in one file. Say /baton.

Baton is plain Markdown with YAML frontmatter — no runtime, no dependencies. Install globally for Claude Code, or per-project. It also works with Codex and Gemini CLI setups that read a skills/ directory.

Install instructions Read the skill

Baton is a derivative of the handoff skill from metaswarm by Dave Sifry (MIT). The structure, method, and template come from metaswarm; Baton adds Section 0, the SWARM fan-out directive, the “latest, never pinned” rule, and a framework-agnostic generalization.
