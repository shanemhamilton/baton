What makes Baton different

Section 0: the next session's contract.

Most handoffs say what to do next. Baton preserves everything material and the exact stopping point, surfaces any high-leverage human choice, queues the best verified runtime capabilities, and launches the longest safe execution horizon with an adversarial evidence spine.

The rules it encodes

Complete continuity — preserve every important result, decision, active lane, recovery state, exact stop point, next move, and do-not-redo boundary.

Ranked capability activation — inspect each receiving Claude or Codex runtime, rank installed and installable paths, prefer authoritative MCP, and queue each real capability with its first use and fallback.

Better-tool installation — research provider-primary and runtime-catalog options before accepting manual work; ask the human to connect the optimal missing option or explicitly defer.

Least-sufficient models — assign every lane to FAST/Haiku-class, BALANCED/Sonnet-class, or FRONTIER; frontier execution requires proof that both lower tiers are insufficient.

Efficient orchestration — keep frontier models on planning, synthesis, integration, and review while efficient workers execute search, extraction, logs, mechanical coding, and tests.

Adversarial truth — classify load-bearing claims, hunt contradictions, use a fresh challenger, and rerun decisive checks.

One-shot momentum — establish a runnable walking skeleton when new structure is needed, then keep expanding and verifying until done or a real hard stop.

## 0. Receiving Session Contract - Shape: LEAN native delegation - Depth: standard, outcome-level - Activate: ranked MCP source · efficient-frontier · ponytail - Install: optimal missing connector / human defer - Models: scans→FAST · coding→BALANCED · synthesis→FRONTIER - Human input: cleared / answered / deferred - Why: 3 independent evidence checks - Resume: exact stop point; do not repeat discovery - Horizon: walking skeleton → vertical slices - Review: fresh falsification challenger - Boot: refresh repo, tracker, locks, runtime - Keep going: verify, repair, take next slice - Stop: only DoD, approval, or hard blocker
Anatomy of a handoff

Only as much detail as the work earns.

Narrow, low-uncertainty work merges the essentials into a compact six-section handoff. Substantial and governed work can use the fuller map below without turning every future edit into a script.

Get going

One file. Native in Codex and Claude.

Baton is plain Markdown with YAML frontmatter — no runtime or package dependencies. Install it globally for both platforms, then invoke $baton in Codex or /baton in Claude Code.

Install instructions Read the skill

Baton is a derivative of the handoff skill from metaswarm by Dave Sifry (MIT). The self-contained handoff structure and exact launch sentence come from metaswarm; Baton adds a human leverage gate, comprehensive momentum preservation, MCP and capability activation planning, mandatory least-sufficient model assignment, efficient capable-model orchestration, adversarial evidence checks, long one-shot missions, and walking-skeleton guidance.
